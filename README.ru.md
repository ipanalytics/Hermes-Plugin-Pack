# Hermes Plugin Pack

Четыре плагина, которые мы гоняем каждый день на Hermes Agent. Они намеренно маленькие: один
файл Python, никаких сторонних зависимостей, одна задача, которой в стандартном агенте нет.

Большинство примеров плагинов — демки. Здесь то, что выжило месяцы ежедневной работы: журнал
оценок, черновик навыков, песочница для команд и компакция контекста, которая ничего не
переписывает.

## Что внутри

| Плагин | Какую боль закрывает | Куда встраивается | Что нужно |
| --- | --- | --- | --- |
| `feedback-reactions` | Отметки 👍/👎 в чате пропадают в никуда | событие `gateway_platform_event` | ничего |
| `skill-factory` | Один и тот же порядок работы повторяется руками каждую неделю | `post_tool_call` + 5 команд | ничего |
| `proot-sandbox` | Команда агента может прочитать секреты и домашний каталог | провайдер терминала | сборка `proot` |
| `jev_compact` | Компакция переписывает весь транскрипт и теряет детали | хук `pre_llm_call` | ключ TypeSafe |

### `feedback-reactions`

Реакции в Telegram приходят как события платформы, хост отдаёт их только для авторизованных,
поэтому фильтровать вручную не нужно. Плагин переводит набор эмодзи в вердикт и дописывает
строку в `$HERMES_HOME/data/feedback.jsonl` — туда же, где уже лежат текстовые вердикты, так что
существующий недельный разбор продолжает работать без правок. Хук гасит свои ошибки сам:
наблюдатель не имеет права уронить шлюз.

### `skill-factory`

Пассивно пишет вызовы инструментов сессии в ограниченное окно на 500 событий, считает одиночные
инструменты и пары. Всё, что повторилось больше одного раза, — кандидат в навык: именно повтор и
есть признак, что процедуру стоит записать. `/skill-factory-propose` не умничает: печатает
кандидатов и даёт агенту конкретное задание — прочитать записанные события, выбрать **одну**
процедуру, оформить её инструментами навыков и запомнить имя. Состояние —
`$HERMES_HOME/plugin-data/skill-factory/`, запись атомарная.

Идея: `Romanescu11/hermes-skill-factory`, переписано под текущий контракт плагинов
(`register(ctx)` + `ctx.register_hook` / `ctx.register_command`), поэтому `hermes plugins doctor`
проходит и поверхность реально привязывается.

### `proot-sandbox`

Бэкенд терминала: команды идут под `proot` (userspace, без root), единственное доступное на
запись дерево — `/workspace`. Домашний каталог агента (`sessions`, `memories`, `config.yaml`,
`.env`, ключи профилей) просто не примонтирован: команда не прочитает то, чего там нет. Домашний
каталог пользователя подменяется пустышкой, ключи провайдеров вырезаются из окружения перед
запуском, доступность видна в обычных проверках `doctor`, таймаут возвращает код 124, а не
вешает инструмент. Пути берутся из `$HERMES_HOME`; единственное внешнее требование — бинарь
`proot`.

### `jev_compact`

Обычная компакция суммаризирует: модель заново пишет вашу историю, и детали тихо меняются. Здесь
маленькая быстрая модель оценивает каждый вызов инструмента и отвечает на один вопрос — держать,
укоротить или выбросить. Устаревшие вызовы и их результаты вырезаются, всё остальное остаётся
**дословно**: ничего не пересказано, не придумано и не слито вместе. Решение стоит одного
дешёвого вызова, каждое пишется в `$HERMES_HOME/data/jev_compact_decisions.jsonl`, так что видно,
что именно выкинули. Если модель недоступна, плагин сдаётся в открытую — транскрипт не трогается.
Нужен ключ TypeSafe. Идея: `tamaratran/fast-jev-compaction` (MIT); это независимая реализация, не
копия.

## Чего здесь сознательно нет

Мы пользуемся ещё тремя плагинами других авторов. Они под MIT и живут в апстриме, поэтому мы
даём ссылки, а не тащим чужой код к себе:

- `hermes-jev` — Steve Darlow (MIT): решения TypeSafe для маршрутизации, фильтрации памяти, выбора
  действий.
- `hermes-handoff` — Steve Darlow (MIT): закрыть сессию и открыть следующую с капсулой.
- `typesafe-skill-router` — Ritesh Patel (MIT): называет один навык, который стоит загрузить.

Скопированный плагин — это чужая поддержка у вас на руках и потерянные обновления. Ставьте
апстрим, фиксируйте версию, а свой набор держите для того, что написали сами.

## Установка

```sh
mkdir -p "${HERMES_HOME:-$HOME/.hermes}/plugins"
cp -r plugins/* "${HERMES_HOME:-$HOME/.hermes}/plugins/"
hermes plugins doctor
```

Лишний плагин просто не копируйте. `proot-sandbox` дополнительно хочет `HERMES_PROOT_BIN`, если
`proot` не лежит в `PATH`.

## Что мы поняли про свои плагины

Плагин — это каталог с `plugin.yaml` и `__init__.py` с функцией `register(ctx)`. Правила, которые
не дают плагину превратиться в проблему:

1. **Не ронять шлюз.** Каждый хук целиком в `try/except` и тихий выход. Сломанный наблюдатель не
   должен ломать доставку сообщений.
2. **Ограниченное состояние.** JSON-файл с фиксированным окном лучше базы, которую надо мигрировать.
3. **Стандартная библиотека вперёд.** Из четырёх плагинов здесь ни один не тянет ничего лишнего, а
   зависимость — это обещание её поддерживать.
4. **Объявлять требования.** `requires_env` для секретов, `config_schema` для настроек: хост тогда
   скажет, чего не хватает, вместо падения при импорте.
5. **Писать авторство.** Если идея чужая — сказать это в шапке и дать ссылку.

Используемые хуки: `gateway_platform_event`, `post_tool_call`, `pre_llm_call` плюс поверхность
провайдера терминала для бэкендов.

## Состояние и тесты

```sh
python -m pytest -q      # 39 passed
python -m ruff check .   # чисто
```

| Плагин | Тестов | Что покрыто |
| --- | --- | --- |
| `feedback-reactions` | 7 | разбор эмодзи в вердикт, форма строки журнала, чужие события, битые payload’ы, привязка хука |
| `skill-factory` | 10 | окно на 500 событий, подсчёт повторов, вывод `propose`, save/list/clear, атомарная запись |
| `proot-sandbox` | 9 | таблица монтирований (корень дома не примонтирован), вырезание ключей, пути из `$HERMES_HOME`, имя домашнего каталога внутри, таймаут → 124 |
| `jev_compact` | 13 | сопоставление вызова и результата, удаление пары, сжатие вместо удаления, защита головы и хвоста, разбор ответа, журнал решений, поведение без ключа и при падении API |

Тесты грузят плагины так же, как хост — по пути, с поддельным `ctx`, — и не ходят в сеть: вызов
TypeSafe подменён, `subprocess` тоже. Всё, что плагины пишут, уходит в одноразовый `$HERMES_HOME`
в `tmp_path`.

Чего тесты **не** доказывают: что внутри живого процесса Hermes всё ведёт себя так же. Это
по-прежнему «работает в проде каждый день» — именно так и нашлись баги, которые здесь закрыты.

## Требования, лицензия, приватность

- Hermes Agent с плагинным API (`manifest_version: 2`), Python 3.11+.
- MIT.
- Никакой телеметрии. С машины ничего не уходит, кроме вызовов моделей, которые хост делает и без
  нас; `jev_compact` ходит в TypeSafe, потому что в этом весь его смысл.
